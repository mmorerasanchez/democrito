## Role

Act as a developer cleaning up package manager ambiguity in an npm-based
project. You understand gitignore patterns and lockfile semantics.

## Context

democrito uses npm as its package manager (`package-lock.json` exists,
README says `npm install`). A `bun.lockb` file (245KB binary) was
auto-generated by Lovable's build environment and committed to the repo.
Its presence contradicts the npm-only convention and confuses contributors.

## Task

Delete `bun.lockb` from the repo and add it to `.gitignore` so it
cannot be re-committed.

## Steps

1. Verify `package-lock.json` exists at the repo root (it should)
2. Delete `bun.lockb`
3. Add `bun.lockb` to `.gitignore`
4. Verify `.gitignore` doesn't already have conflicting entries

## Constraints

- DO NOT delete `package-lock.json` — it is the canonical lockfile
- DO NOT add any other lockfiles to gitignore beyond `bun.lockb`
- DO NOT modify `package.json`
- If any requirement is unclear, ask before writing code
